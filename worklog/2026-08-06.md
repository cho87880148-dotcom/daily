CSS 애니메이션은 `from`→`to` 를 반복하는 구조라 값을 아무리 흩어놔도
결국 정해진 길의 왕복으로 보인다. **CSS 로는 이 요구를 만족시킬 수 없다.**

`requestAnimationFrame` 으로 매 프레임 위치를 직접 계산하도록 바꿨다.

- 공마다 독립적인 속도·방향 벡터
- **매 프레임 무작위 바람** ← 경로가 반복되지 않는 핵심

**추첨 중에는 목표 속도(`physTarget`)만 올린다.** 움직이는 방식은 동일하므로
사용자가 요청한 "그 패턴을 유지한 상태에서 공이 나오게"가 그대로 성립한다.
뽑힌 공은 `physBalls` 배열에서 빼고 나머지는 계속 돈다.

> 다른 탭으로 가면 `visibilitychange` 로 계산을 멈춘다. 안 그러면 배터리를 계속 먹는다.
> `prefers-reduced-motion` 을 켠 경우엔 물리 계산을 아예 돌리지 않는다.

>    사용자 캡처를 보니 **처음부터 `GitHub Actions` 로 정확히 설정돼 있었다.**
>
> **로그를 못 볼 때는 추측을 근거처럼 말하지 말 것.** 사용자에게 화면을 요청하는 편이 빨랐다.


### ① ★ 검색어 시각이 UTC 로 찍히고 있었다

사용자: "기준이 오전 10시 57분인데 최신이 아닌 것 같다"

**자료는 최신이었고 표시된 시각만 틀렸다.** 실측:

```
지금 한국시각      20:13
배포본의 updated   10:57   ← 9시간 어긋남
실제 받아온 시각   19:57 (한국시각)
```

`fetch-trends.ps1` 이 `(Get-Date)` 를 썼는데 **GitHub 서버는 UTC** 라
그 시각이 그대로 찍혔다. `[DateTime]::UtcNow.AddHours(9)` 로 고쳤다.
윈도우·리눅스 양쪽에서 똑같이 동작한다.

> 옆 폴더 newhome 의 CLAUDE.md 함정 6번(날짜는 ConvertTo-Utc 로만)과 **같은 계열의 사고**다.
> 이 프로젝트에서도 한 번 밟았다. 시각을 파일에 적을 때는 항상 어느 시간대인지 정할 것.

### ② 갱신 주기를 30분으로

`cron: '0 * * * *'` → `'0,30 * * * *'`.
**GitHub 예약 실행은 정확하지 않다** — 서버가 바쁘면 5~20분 밀린다. 사용자에게 알렸다.

### ③ ★ 서비스워커가 저장본을 먼저 주고 있었다

원래 `caches.match` 를 먼저 보고 없을 때만 받아오는 방식이라,
**앱을 고쳐서 올려도 폰에는 옛 화면이 계속 나왔다.** 고칠 때마다 `CACHE` 숫자를
올려야 하는데 잊기 쉽다. 새로 받기를 먼저 하고 실패하면 저장본을 쓰도록 뒤집었다(v2).
파일이 몇 KB 라 속도 손해는 없다.

### ④ 아이콘을 사용자 사진으로 교체

카카오톡으로 받은 포메라니안 사진(2000x2000). `icon-source.jpg` 로 프로젝트에 넣고
`make-icons.ps1` 이 거기서 180/512 를 만들도록 다시 썼다. 글자를 그려넣던 방식은 버렸다.

`manifest.json` 의 `purpose` 를 `any maskable` → `any` 로 바꿨다.
**maskable 은 가장자리를 비워둔 그림 전용**이라 사진을 넣으면 원형으로 잘려 귀가 날아간다.

앱 이름(`오늘`)은 그대로 뒀다 — 사용자가 홈 화면 추가할 때 직접 정하기로 했다.
